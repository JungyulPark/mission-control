# LOOP 엔지니어링 플랜 — kfortunes 추진 사이클

> 발령: mission-control(관제탑). 목표: **kfortunes를 "AdSense 승인 + 첫 색인 트래픽"까지** 반복 사이클로 밀어올린다.
> 성격: 관제탑은 코드를 직접 안 짠다(레포 분리). 루프 = **검토→다음 한 가지 선정→해당 세션에 명령 발령→STATE 갱신**의 반복.

## 왜 "자동 타이머 루프"가 아니라 "게이트 루프"인가
실제 코드는 kfortunes 세션에서 돌고, **각 단계마다 사람 눈 검증**이 필요(사이트 실제 렌더·AdSense 정책·카피 품질). 따라서:
- 무인 타이머 루프(❌) — 검증 없이 쌓이면 thin/오류 누적.
- **게이트 루프(✅)** — 마일스톤마다 사용자 확인 후 다음 반복. `/loop`은 *상태 폴링·리마인더* 용도로만 보조.

## 루프 1회 반복 = 5스텝 (관제탑이 매번)
1. `ops/STATE.md` 읽고 현재 마일스톤 위치 확인.
2. 직전 산출물(세션 결과·사용자 검증) 반영.
3. **단일 다음 액션** 1개 선정(레버리지 최대, 한 번에 하나 원칙).
4. 해당 세션용 **한 줄 명령** 발령(`ops/design-directive.md` 템플릿).
5. STATE 갱신 + 커밋. 마일스톤 게이트면 → 사용자 확인 요청 후 정지.

## 마일스톤 게이트 (kfortunes)
| # | 게이트 | 담당 | 완료 기준(검증 포인트) |
|---|---|---|---|
| **M0** | 프로젝트 검증 | **사용자(지금)** | 레포 복원 상태·사이트 접속 여부·48edd60 자산 실재 확인 |
| **M1** | result 롱폼 정적화 | kfortunes 세션 | `supanova-redesign-engine`으로 result.html → §3-(B) 8섹션, GPT호출 0, 모바일 렌더 OK |
| **M1.5** | 필수 정적페이지 | kfortunes 세션 | 소개/개인정보/약관/문의 + "오락목적" 디스클레이머 |

각 게이트는 **앞 게이트 통과 전 다음으로 안 넘어간다**(한 번에 하나).

## `/loop` 보조 사용 (선택)
무인 추진이 아니라 **리마인더**로:
- `/loop 1d 진척 점검: STATE 읽고 다음 한 가지 브리핑` — 하루 1회 관제탑이 다음 액션을 상기시킴.
- 게이트 통과는 항상 사용자 확인 필요 → 루프는 "다음에 뭐 할지"를 잊지 않게 하는 장치.

## 안전장치 (매 반복 재확인)
- 결제·백엔드·실시간 GPT 부활 금지(정적 먼저).
- 한 번에 하나 — 동시에 여러 마일스톤 권하지 않음.
- 연구 레포는 이 루프에 넣지 않음(다른 시계).

## 종료 조건
M3 통과(AdSense 승인 + 첫 색인 트래픽) → 루프 1차 목적 달성. 이후 "에버그린 양산 루프"로 전환(별도 플랜).
