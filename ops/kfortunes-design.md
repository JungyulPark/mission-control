# kfortunes 리디자인 설계 브리프 (전달용)

> 목적: 각 레포 세션(kfortunes)이 따라 구현할 **디자인 기준 문서**.
> 제약: 정적 먼저 · 결제 영구제외 · GPT실시간→풍부한 정적콘텐츠 · 모바일 우선 · AdSense 통과가 1차 목표.
> 벤치마크: 16Personalities(설명력·구조), Co-Star(브랜드·바이럴), 포스텔러(국내 사주 UX).

---

## 0. 한 줄 포지셔닝
"사주를 **읽을거리**로 만든다." — 점괘 한 줄이 아니라, 16Personalities처럼
**길고 구조화된 인물 해설**을 정적으로 제공. 이게 AdSense 본체이자 체류시간이다.

각 벤치마크에서 훔칠 것:
- **16Personalities** → 결과 페이지의 "길고 읽고 싶은 구조"(섹션·차트·강약점·관계). thin content의 반대.
- **Co-Star** → 대담한 흑백 미니멀 + 공유하고 싶은 카피 톤. 바이럴 카드.
- **포스텔러** → 국내 사주 정보구조(일간/오행/십성)와 모바일 인터랙션의 친숙함.

---

## 1. 디자인 원칙 (5)
1. **모바일 우선.** 국내 사주 트래픽 절대다수가 모바일. 360–390px에서 먼저 완성하고 데스크톱은 중앙 1컬럼 확장.
2. **콘텐츠 우선, 광고는 사이.** AdSense는 본문 사이 자연 삽입. 첫 화면(above the fold) 광고 도배 = 거부 사유. 콘텐츠:광고 비율 압도적으로 콘텐츠.
3. **한 페이지 = 한 질문.** 입력→결과 한 흐름. 산만한 메뉴 금지.
4. **대담하게 미니멀.** 색 2~3개, 폰트 2개. 화려함이 아니라 **여백과 타이포 위계**로 고급져 보이게.
5. **공유가 기본동작.** 모든 결과 하단에 "이미지로 저장/공유" — 바이럴 깔때기의 입구.

---

## 2. 비주얼 시스템

### 색 (다크 우선, 신비로운 톤)
- 배경: `#0E0E12` (딥 잉크) / 카드: `#17171E`
- 텍스트: `#F2F0EA` (웜 화이트) / 보조: `#A09CB0`
- 액센트 1: `#D4AF37`(골드 — 오행/강조선·CTA). 액센트 2: 오행 컬러팔레트(목靑/화赤/토黃/금白/수黑)는 데이터 시각화에만.
- 라이트 모드는 P2. 우선 다크 한 벌.

### 타이포
- 헤드라인: 명조 계열(예: `Noto Serif KR` 700) — 사주의 "고전·권위" 톤.
- 본문: 고딕 계열(`Pretendard` 또는 `Noto Sans KR`) — 가독성.
- 위계: H1 32–40 / H2 24 / 본문 16–17 / 캡션 13. 행간 1.7(한글 본문은 넉넉히).
- 영문판은 Serif=`Fraunces`/`Playfair`, Sans=`Inter`.

### 형태
- 라운드 16px 카드, 얇은 1px 보더(`#2A2A35`), 은은한 그림자.
- 구분선·장식은 골드 헤어라인 1px. 이모지 남발 금지(아이콘은 단색 라인).

---

## 3. 페이지 구조

### (A) 랜딩 — 입력
- 히어로: 큰 명조 H1 + 한 줄 약속("당신의 사주, 깊이 읽어드립니다") + 생년월일시 입력 폼 즉시 노출(스크롤 없이).
- 입력은 4필드(년/월/일/시) + 양력/음력 토글 + 성별. 시 모름 옵션.
- CTA 1개(골드 풀폭 버튼). 그 아래 "무엇을 알려주나요?" 정적 설명 섹션(SEO·신뢰).

### (B) 결과 — ⚠️ 최우선 재설계 (현 result.html = 빨간불, 382단어 GPT동적)
**16Personalities식 롱폼 정적 리포트로 전환.** 결정론 엔진이 산출한 사주 데이터 →
미리 집필된 해설 DB를 **조합**해 길게 렌더(GPT 호출 0).

권장 섹션 순서:
1. **요약 카드** — 일간/오행 분포 도넛차트 + 한 줄 캐릭터 라벨(공유용 핵심).
2. **사주 원국 표** — 사주팔자 8글자 시각화(오행 컬러).
3. **타고난 성향** — 일간 기반 정적 해설(300자+).
4. **오행 밸런스** — 막대/도넛 + 과다·부족 해설.
5. **십성/육친** — 재물·관계·직업 경향(각 정적 단락).
6. **올해의 흐름** — 세운 간단 해설(연 1회 갱신 정적).
7. **관계 궁합 티저** — "상대 사주와 비교 →" 바이럴 경로 입구.
8. 공유 카드 저장 + 관련 읽을거리(에버그린 내부링크).

→ 한 결과가 **스크롤 길고 정보 빽빽**해야 한다. 이게 AdSense·체류시간·SEO 셋 다 잡는 핵심.

### (C) 에버그린 허브 (AdSense 본체)
- "일간별 사주 풀이"(갑목~계수 10개), "오행 가이드", "십성 사전" 등 정적 아티클 군.
- 각 1500자+ 독립 페이지. 결과 페이지에서 내부링크로 연결 → 색인·권위.

---

## 4. 바이럴 공유 카드
- 결과 요약을 **세로 1080×1920(스토리)** + **정사각 1080** 두 포맷 이미지로.
- 구성: 딥 배경 + 골드 핵심 라벨("당신은 ○○한 갑목") + 오행 미니차트 + 워터마크(kfortunes.com).
- 구현: 클라이언트에서 `html2canvas` 또는 `<canvas>`로 정적 생성(백엔드 0). Co-Star처럼 "캡처해서 인스타 올리고 싶은" 톤이 성패.
- 궁합 결과는 특히 공유율 높음 → 별 경로로 강하게.

---

## 5. AdSense 배치 규칙 (재신청 통과 기준)
- 신청 시점엔 광고 적게/없이도 됨 — **콘텐츠 충실도**가 심사 핵심.
- 통과 후 배치: 결과 섹션 사이 1~2개(인콘텐츠), 아티클 하단 1개. above-the-fold 큰 광고·전면광고 금지.
- 필수 정적 페이지: 소개/개인정보처리방침/이용약관/문의 — 없으면 거부. (사주는 "오락 목적" 디스클레이머 권장.)
- thin/자동생성 느낌 회피: 결과가 충분히 길고 사람이 쓴 해설처럼 읽혀야 함.

---

## 6. 듀얼언어
- 구조는 `/ko/`, `/en/` 경로 분리(또는 서브도메인). **주력 1개 언어로 콘텐츠 완성·AdSense 통과 후** 확장.
- 기계번역으로 양쪽 동시 = duplicate/thin 위험 → 금지. 영문판은 K-culture 톤으로 별도 카피.

---

## 7. 구현 메모 (정적 스택)
- 순수 정적(HTML/CSS/JS) 또는 정적 생성기. 엔진=클라이언트 JS(결정론, 기존 자산 재사용).
- 해설 DB = JSON/MD로 분리 → 엔진 결과 키로 조합 렌더. 집필은 점진 확장 가능.
- 폰트는 셀프호스트 또는 `display=swap`. CLS 방지.
- 라이트하우스 모바일 90+ 목표(AdSense·SEO 둘 다 유리).

## 우선순위
**P0: result.html → 롱폼 정적 리포트 재설계(섹션 1·2·3 먼저).**
그다음 공유카드 → 에버그린 허브 → 영문 확장. 결제·실시간 GPT는 부활시키지 않는다.

## 8. supanova 디자인 스킬 설치 (kfortunes 세션에서 실행)
`uxjoseph/supanova-design-skill` = 플러그인 아님. **SKILL.md 묶음**(한국어 랜딩 최적화,
Tailwind CDN + Pretendard + Solar 아이콘). 정상 frontmatter 확인됨 → `.claude/skills/`에
넣으면 Skill 도구로 호출 가능. **kfortunes 레포 루트에서:**

```bash
git clone --depth 1 https://github.com/uxjoseph/supanova-design-skill /tmp/supanova
mkdir -p .claude/skills
for d in taste-skill redesign-skill output-skill soft-skill; do
  cp -r "/tmp/supanova/$d" ".claude/skills/$d"
done
git add .claude/skills && git commit -m "skills: add supanova design skills"
```

설치 후 세션 새로고침 → Skill 목록에 `supanova-redesign-engine`,
`supanova-design-engine` 등 노출.
- **result.html 재설계** → `supanova-redesign-engine` (스캔→진단→수정→우선순위 4단계).
- **새 페이지(랜딩/에버그린)** → `supanova-design-engine`.
- 출력 잘림 방지 `output`, 미감 기준 `soft` 보조.

⚠️ 주의: 이 스킬의 스택은 **Tailwind CDN + standalone HTML**. 우리 "정적 먼저" 원칙과
부합(백엔드 0). 단 스킬은 *랜딩페이지/전환* 최적화라 사주 **결과 롱폼**엔 §3-(B) 구조를
입히는 토대로 쓰고, 카피·정보밀도는 본 브리프 기준을 우선한다.
